## Summary

Six open P2 findings: five helper bugs and one test defect. The failures
concentrate in dependency interpretation and parsing Bash source as plain
text. Existing tests pass because package stubs accept invalid marking
operands, metadata is supplied independently of the edited PKGBUILD, and
one refresh assertion can reuse evidence from a preceding invocation.

No actionable defect was confirmed in the five committed package

## Invariants

- A successful refresh must check generic dependencies and dependencies
  for the active architecture, including when the package version matches.
- Requirements, virtual provides and installed package names are distinct
  inputs. Dependency checks and installation may consume requirements;
  changes to install reasons must select installed packages that satisfy
  the complete requirement.
- Updating one metapackage must not change unrelated packages' explicit
  install reasons or include unrelated staged files in its commit.
- Literal edits must recognize actual Bash assignments and array bounds,
  respecting comments and quoted strings without executing expressions.
  Unsupported input must be rejected before overwriting the PKGBUILD.
- Dependency installation precedes the local package build; a failed
  operation must not create a success commit, and edits remain available
  for diagnosis.
- Checks must stay inside disposable fixtures, preserve checkout/index
  state, and fail on an empty, skipped or failing suite. Each assertion
  about a command invocation must use evidence from that invocation.
- Design acceptance remains separate from demonstrated behavior. Mocked
  tests establish neither native Arch nor Docker operation.

## Findings

### Open and Moved

- `update-marks-raw-requirements` — **Updates pass requirements instead of installed names to dependency marking.** Bug · Open · Verified.
  - Where: `mpkg:223-224` (`update`) at the reviewed commit.
  - Severity: P2.
  - After a successful build, a requirement such as `git>=2`, or `virtual`
    supplied by an installed package named `provider`, is forwarded
    unchanged to `pacman -D --asdeps`. That operation updates installed
    packages, so these operands fail even though dependency installation
    succeeded; the command exits without committing. Resolve satisfying
    installed names before marking and test with a stub that rejects
    unknown names. See the [pacman database operation](https://man.archlinux.org/man/pacman.8.en#DATABASE_OPTIONS_(APPLY_TO_-D)).
  - Evidence: both `git>=2` and `virtual` cases reached `makepkg -si`, then
    failed the installed-name-only marking stub with exit 1; fixture HEAD
    remained unchanged. This verifies command construction and failure
    handling, not a real package installation.
  - Review backlog: `resolve-installed-dependency-targets`

- `refresh-selects-unsatisfying-providers` — **Refresh demotes providers that do not satisfy the dependency version.** Bug · Open · Verified.
  - Where: `mpkg:113-119` (`installed_providers`), used by `refresh` at
    `mpkg:145`, at the reviewed commit.
  - Severity: P2.
  - The resolver discards the requirement's version and compares only
    names, returning every matching provider. With installed packages
    providing `virtual=1` and `virtual=2`, `virtual>=2` selects both; an
    unrelated explicitly installed older provider is marked as a
    dependency and can subsequently become an orphan. Preserve version
    semantics when choosing satisfying installed packages, including
    direct-name matches, before changing installation reasons.
  - Evidence: direct invocation of `installed_providers` with those two
    records returned `['new-provider', 'old-provider']` for `virtual>=2`.
    The downstream marking call was inspected; no host reasons changed.
  - Review backlog: `resolve-installed-dependency-targets`

- `dependency-comment-closes-array` — **A closing parenthesis in a comment corrupts dependency edits.** Bug · Open · Verified.
  - Where: `mpkg:149` (`literal_dependencies`), replacement at `mpkg:208`
    and write at `mpkg:220`, at the reviewed commit.
  - Severity: P2.
  - The non-greedy array regex stops at `)` inside a legal Bash comment.
    In an array containing `git # base (required)` followed by `python`,
    it parses only `git`; replacement leaves `python` and the real closing
    parenthesis outside the new array. The file is overwritten before
    package tooling detects the syntax error. Recognize comment-aware
    array bounds or reject unsupported syntax before writing.
  - Evidence: the original fixture passed `bash -n`; parsing and replacing
    its array with the helper functions omitted `python` from the parsed
    set and produced a file for which `bash -n` exited 2.
  - Review backlog: `parse-pkgbuild-literal-boundaries`

- `quoted-description-counts-as-assignment` — **Descriptions containing assignment-shaped lines prevent later edits.** Bug · Open · Verified.
  - Where: `mpkg:190-194` (`update`), description serialization at
    `mpkg:216-218`, at the reviewed commit.
  - Severity: P2.
  - Creating a metapackage with the multiline description
    `Tools\npkgrel=7\nfor development` succeeds and safely quotes the
    description, but the next `+python` edit counts that quoted line as a
    second release assignment and refuses to proceed. Restrict metadata
    lookup to actual assignments outside strings, so input the helper
    generates remains editable. Apply the same boundary rule to array
    discovery rather than treating quoted description text as source.
  - Evidence: public command invocations in a stubbed fixture returned 0
    on creation, then 1 with `Cannot increment pkgrel: expected one integer
    assignment.` on editing.
  - Review backlog: `parse-pkgbuild-literal-boundaries`

- `refresh-omits-architecture-dependencies` — **Refresh reports success without checking architecture dependencies.** Bug · Open · Verified.
  - Where: `mpkg:133-145` (`refresh`), contrasted with `install` at
    `mpkg:45`, at the reviewed commit.
  - Severity: P2.
  - `refresh` reads only generic `depends`, although installation already
    supports `depends_<machine>`. When the installed metapackage version
    matches and a dependency exists only in the active architecture's
    list, refresh says it is up to date without checking, installing or
    marking that dependency. Use the same active dependency set in both
    operations and cover mixed generic/architecture lists as well.
  - Evidence: stub metadata contained `depends_<os.uname().machine> =
    virtual`, matching installed version `1-1`, and a missing-dependency
    response. Refresh returned 0; the log contained only
    `makepkg --printsrcinfo` and `pacman -Q vhata-test`, with no `pacman -T`
    or installation/marking call.
  - Review backlog: `refresh-active-architecture-dependencies`

- `refresh-test-reuses-command-log` — **The missing-dependency refresh test can pass without rebuilding.** Test · Open · Verified.
  - Where: `tests/test_mpkg.py:176-180`
    (`test_refresh_no_rewrite_or_commit_and_provider_resolution`) at the
    reviewed commit.
  - Severity: P2.
  - The outdated-version case records `makepkg -sif`, then the
    missing-dependency case searches the same accumulated log. Its
    assertion therefore passes even if the second command never rebuilds.
    Clear the log or inspect only each invocation's appended records, and
    assert the relevant sequence separately for each case.
  - Evidence: removing the missing-dependency predicate from a temporary
    copy of `mpkg:138` left this targeted test passing (one test, no
    failures). The repository source was unchanged.
  - Review backlog: `isolate-refresh-test-call-evidence`

## Suggested order of work

1. Isolate the refresh test's call evidence so later behavior fixes have
   a meaningful regression gate.
2. Correct dependency target/provider resolution, preserving install
   reasons for packages that do not satisfy the requirement.
3. Correct literal Bash boundaries, checking both source preservation
   and syntax before any package subprocess runs.
4. Include active architecture dependencies in refresh and verify that
   dependencies for other architectures are excluded.

Each fix should rerun its original scenario and the documented entrypoint,
and receive independent review. These are existing-helper repairs;
implementation of the future server manager remains separately gated.
